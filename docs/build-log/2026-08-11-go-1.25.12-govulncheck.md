# Go 1.25.12 Govulncheck Follow-Up

## Metadata
- Date: 2026-08-11
- Scope: toolchain/security gate
- Branch: `fix/go-1.25.12-govulncheck`

## Problem
- The CI `dependency-verification` job started failing in `govulncheck` on the Go 1.25.10 standard library.
- The reported reachable findings were:
  - `GO-2026-5856` in `crypto/tls`, fixed in Go 1.25.12.
  - `GO-2026-5039` in `net/textproto`, fixed in Go 1.25.11.
  - `GO-2026-5037` in `crypto/x509`, fixed in Go 1.25.11.
- With the repository pinned to Go 1.25.10, no PR can pass the required dependency-verification gate.

## Approach
- Updated the module Go baseline from 1.25.10 to 1.25.12.
- Updated CI Go setup from 1.25.10 to 1.25.12 for dependency verification, lint, and test jobs.
- Updated release workflow Go setup from 1.25.10 to 1.25.12 for release verification/package jobs and Windows MSI packaging.
- Recorded the security-gate follow-up in the build status tracker.

## Risk and Mitigation
- Risk: Go 1.25.12 could introduce patch-level behavior changes.
- Mitigation: this stays within the existing Go 1.25 patch line and targets standard-library security fixes reported by the required vulnerability gate.
- Risk: actions/setup-go may not have the new patch version available yet.
- Mitigation: CI will prove availability before merge; local verification uses the same `GOTOOLCHAIN=go1.25.12+auto` baseline where needed.

## Verification
- Commands run:
  - `git diff --check`
  - `GOTOOLCHAIN=go1.25.12+auto go version`
  - `GOTOOLCHAIN=go1.25.12+auto go mod verify`
  - `GOTOOLCHAIN=go1.25.12+auto go install golang.org/x/vuln/cmd/govulncheck@v1.1.4`
  - `GOTOOLCHAIN=go1.25.12+auto GOCACHE=/tmp/go-build $(go env GOPATH)/bin/govulncheck ./...`
  - `pnpm install --frozen-lockfile`
  - `GOTOOLCHAIN=go1.25.12+auto make fmt`
  - `make check`
  - `GOTOOLCHAIN=go1.25.12+auto GOCACHE=/tmp/go-build GOLANGCI_LINT_CACHE=/tmp/golangci-lint make lint` - failed before linting package bodies because this linked worktree could not provide Go VCS stamping metadata.
  - `GOFLAGS=-buildvcs=false GOTOOLCHAIN=go1.25.12+auto GOCACHE=/tmp/go-build GOLANGCI_LINT_CACHE=/tmp/golangci-lint make lint`
  - `GOTOOLCHAIN=go1.25.12+auto GOCACHE=/tmp/go-build make test`
  - `GOTOOLCHAIN=go1.25.12+auto GOCACHE=/tmp/go-build make build` - failed before compiling package bodies because this linked worktree could not provide Go VCS stamping metadata.
  - `GOFLAGS=-buildvcs=false GOTOOLCHAIN=go1.25.12+auto GOCACHE=/tmp/go-build make build`

## Teach-back
- Security gates tied to the Go vulnerability database can turn red without an application diff when new standard-library findings are published.
- Treat those failures as toolchain lifecycle work: bump the pinned patch release, run the same vulnerability gate, and keep the build log explicit.
